# 잉여인간의 개발일기

퇴사하고 홀로 게임 개발을 시작한 기록. → <https://hlcho426.github.io>

[Chirpy](https://github.com/cotes2020/jekyll-theme-chirpy) 테마(Jekyll)로 만들었고, `main`에 push하면 GitHub Actions가 빌드해서 배포한다.
이 파일은 블로그에는 나오지 않는다. (`_config.yml`의 `exclude`에 들어 있음)

## 카테고리 규칙

카테고리는 **큰 카테고리 → 작은 카테고리** 2단이다. 글 하나에는 아래 표의 **한 줄**만 붙인다. 작은 카테고리가 `-`인 줄은 큰 카테고리만 쓴다.

| 큰 카테고리 | 작은 카테고리 | 무엇을 쓰나 |
|---|---|---|
| 레퍼런스 조사 | 업계 뉴스 | 참고할 만한 게임 업계 소식 (매일 최대 5개) |
| 레퍼런스 조사 | 개발 도구 | 개발할 때 참고할 AI·툴·엔진·워크플로 소식 |
| 레퍼런스 조사 | 기획 연구 | 기획에 도움이 되는 논문과 자료 심층 분석 |
| 게임 제작 공부 | 유니티 | C#, 컴포넌트, 인풋 시스템 등 유니티 기본 기능을 직접 해 보며 공부 |
| 게임 제작 공부 | 유니티 에셋 | Yarn Spinner, Feel 같은 외부 에셋 사용 가이드 |
| 게임 제작 공부 | 3D 모델링 | 직접 해 본 3D 모델링 공부 |
| 게임 제작 공부 | 2D 그림 | 직접 그려 본 2D 이미지 리소스 공부 |
| 개발 일지 | - | 직접 만드는 게임의 제작 기록 |
| 일상 | - | 그 밖의 이야기 |

헷갈릴 때 기준:

- **레퍼런스 조사 vs 게임 제작 공부**: 남이 만든 기술이나 사례를 *조사해서 정리*하면 레퍼런스 조사, 내가 *직접 따라 해 보며 배우면* 게임 제작 공부.
- **업계 뉴스 vs 개발 도구**: 게임·회사·업계 이야기면 업계 뉴스, 내 작업에 쓸 도구와 작업 방식 이야기면 개발 도구.
- **업계 뉴스 vs 개발 일지**: 바깥 소식이면 업계 뉴스, 내 게임 이야기면 개발 일지.
- **유니티 vs 유니티 에셋**: 유니티가 만든 기능(C#, 컴포넌트, 인풋 시스템 같은 유니티 패키지)이면 유니티, 다른 회사나 개인이 만든 에셋이면 유니티 에셋. 에셋 이름은 태그로 단다.
- **더 잘게 나누고 싶을 때**: 작은 카테고리를 새로 만들기 전에 태그(캐릭터, 배경, UI 등)와 시리즈로 먼저 묶는다. 한 칸에 글이 쌓여 찾기 힘들어지면 그때 나누자고 제안한다.

### 카테고리를 쓰는 법

글의 front matter에 위 표의 한 줄을 **큰 카테고리, 작은 카테고리 순서로 띄어쓰기까지 똑같이** 적는다. 한 글자라도 다르면 다른 카테고리가 된다.

```yaml
categories: [게임 제작 공부, 유니티]
categories: [일상]   # 작은 카테고리가 없는 줄
```

### 카테고리를 추가하거나 순서를 바꿀 때

- 사이드바는 큰 카테고리 아래에 작은 카테고리를 펼쳐 보여 준다. 순서와 큰 카테고리 아이콘은 `_data/sidebar_categories.yml`을 따른다.
- 사이드바에는 **글이 하나 이상 있는 카테고리만** 나온다. 빈 카테고리는 페이지가 없어서 링크가 깨지기 때문이다. (유니티 에셋, 3D 모델링, 2D 그림, 개발 일지는 첫 글을 올리면 나온다.)
- 작은 카테고리 이름은 블로그 전체에서 겹치지 않게 짓는다. 카테고리 페이지 주소가 이름만으로 만들어져서, 큰 카테고리가 달라도 이름이 같으면 한 페이지로 합쳐진다.
- 이름을 바꾸면 `_data/sidebar_categories.yml`과 이미 쓴 글들의 `categories:`도 같이 바꿔야 한다. 레퍼런스 조사 아래 이름이면 브리핑 자동화 설정(`tools/briefing/config.json`의 `parent_category`, `category`)도 같이 바꾼다.

## 글 쓰는 법

`_posts/YYYY-MM-DD-영문-제목.md` 파일을 만든다.

```markdown
---
title: 글 제목
date: 2026-10-11 20:00:00 +0900
categories: [개발 일지]
tags: [유니티, 프로토타입]
---

본문
```

- 한 줄만 내리기: 문장 끝에 `<br>`
- 문단 나누기: 빈 줄 하나
- 글 제목에는 카테고리 접두어를 붙이지 않고 구체적인 내용만 쓴다. 카테고리는 `categories` 메타데이터로 표시한다. 정기 브리핑 PR 제목에는 검토 편의를 위해 카테고리 이름을 남긴다.

### 아직 안 올릴 글 (초안)

`_drafts/영문-제목.md`에 날짜 없이 만든다. `_drafts`는 사이트에 나오지 않는다. 올릴 때 `_posts/YYYY-MM-DD-영문-제목.md`로 옮기고 `date:`를 넣는다. 영문 제목 부분이 글 주소(`/posts/영문-제목/`)가 되니 옮길 때 바꾸지 않는다.

### 시리즈 글

여러 편으로 이어지는 글은 front matter에 같은 `series:` 이름을 적고, 본문 맨 위에 `{% include series.html %}` 한 줄을 넣는다. 같은 시리즈 글을 날짜순으로 모아 이전·다음 글과 전체 목차를 보여 준다. 목차에 보일 짧은 이름은 `series_title:`로 따로 적을 수 있다.

```yaml
series: 유니티 C# 일주일
series_title: "기초 Day 1: 스크립트와 변수"
```

- 시리즈 순서는 `date` 순서다. 앞 편보다 늦은 날짜로 올린다.
- 배포할 때 내부 링크 검사(htmlproofer)를 하므로, 아직 안 올린 글로 가는 링크가 있으면 배포가 실패한다. 서로 링크하는 글은 같이 올린다.
- 시리즈 전체에 붙일 안내(누가 썼는지 등)는 `_data/series.yml`에 시리즈 이름별 `note`로 적는다. 목차 상자 맨 위에 모든 글마다 나온다.
- 글마다 `description:`(한 줄 요약)을 꼭 적는다. 없으면 본문 첫 부분인 목차 상자 글자가 검색 요약과 홈 카드 미리보기에 대신 쓰인다.
- 강의 글의 실습 소제목은 `## 직접 해 보기`(유니티 에디터에서 따라 하기), `## 앱에서 연습하기`(학습 앱에서 문제 풀기)로 글자를 똑같이 쓴다. 그러면 주황·파랑 상자와 본문 왼쪽 세로줄이 자동으로 붙는다. 띄어쓰기가 하나라도 다르면 일반 소제목으로 보인다.

### AI가 정리한 글

글쓴이는 나(`_config.yml`의 `social.name`)로 두고, AI가 정리했다는 사실은 본문 맨 위에 밝힌다. 시리즈 글이면 `_data/series.yml`의 `note`가 목차 상자 맨 위에 나오니 거기에 적는다. 본문의 "나"는 블로그 주인인 나이므로, AI가 한 일을 내가 한 것처럼 쓰지 않는다.

## 정기 브리핑 자동화

Codex 앱의 로컬 예약 작업으로 업계 뉴스·개발 도구 데일리와 금요일 기획 연구 큐레이션을 조사·작성하고 유형별 PR로 제출한다. 개발 도구 데일리는 AI뿐 아니라 엔진·IDE·내러티브 테스트·아트 파이프라인을 다루며, 게임 제작의 구체적인 문제와 관련 있는 자료를 우선한다. 별도 유료 모델 API 키는 사용하지 않으며 Codex 구독 사용량을 소비한다. GitHub Actions는 빌드·링크 검사와 PR 미리보기를 맡는다. [설정·수동 테스트·실패 확인 안내](tools/briefing/OPERATIONS.md)를 따른다. 기존 ChatGPT 예약은 변경하지 않는다.

## 커스터마이즈한 곳

| 파일 | 내용 |
|---|---|
| `assets/css/jekyll-theme-chirpy.scss` | 글꼴(카페24 오스퀘어 / 에어), 사이드바 배경과 글자색, 사이드바 작은 카테고리 스타일, 큰 카테고리 페이지의 작은 카테고리 제목 줄, 유니티 캡처 이미지(`assets/img/unitystudy/`) 액자, 강의 글의 '직접 해 보기'·'앱에서 연습하기' 소제목 상자 |
| `_includes/metadata-hook.html` | Chirpy가 모든 페이지 `<head>`에 넣는 자리. 애드센스 코드, 실습 소제목 아래 본문을 묶어 세로줄을 그리는 스크립트 |
| `assets/fonts/` | 웹폰트 파일 |
| `_includes/sidebar.html` | Chirpy v7.6.0 사이드바 복사본. 카테고리 탭 자리에 큰 카테고리와 그 아래 작은 카테고리를 펼치고, 태그·아카이브 탭은 숨김(페이지는 남아 있음) |
| `_layouts/category.html` | Chirpy v7.6.0 카테고리 페이지 복사본. 작은 카테고리가 있는 큰 카테고리는 작은 카테고리별 최신 글 2편을 작은 카드로 보여 줌 |
| `_includes/post-card.html` | 카테고리 페이지의 작은 글 카드 (홈 카드의 절반쯤 높이: 제목·요약 1줄, 날짜, 오른쪽 작은 이미지) |
| `_includes/sub-categories.html` | 큰 카테고리 아래 작은 카테고리 순서 계산 (사이드바와 카테고리 페이지가 같이 씀) |
| `_includes/series.html` | 시리즈 글 목차 상자 (위 "시리즈 글" 참고) |
| `_data/series.yml` | 시리즈별 안내 문구 (목차 상자에 표시) |
| `_data/sidebar_categories.yml` | 사이드바 카테고리 순서와 큰 카테고리 아이콘 |
| `_data/contact.yml` | 사이드바 아래 아이콘 (트위터 숨김) |
| `_tabs/about.md` | 정보 페이지 |
