# 잉여인간의 개발일기

퇴사하고 홀로 게임 개발을 시작한 기록. → <https://hlcho426.github.io>

[Chirpy](https://github.com/cotes2020/jekyll-theme-chirpy) 테마(Jekyll)로 만들었고, `main`에 push하면 GitHub Actions가 빌드해서 배포한다.
이 파일은 블로그에는 나오지 않는다. (`_config.yml`의 `exclude`에 들어 있음)

## 카테고리 규칙

글 하나에 카테고리는 **하나만** 붙인다.

| 카테고리 | 무엇을 쓰나 |
|---|---|
| 게임 개발 브리핑 | 매일 주요 게임 개발 소식 5개 |
| 게임 개발 기술 | 유니티, AI, 아트 파이프라인 등 개발 기술 조사와 정리 |
| 게임 디자인 연구 | 논문과 개발 사례 심층 분석 |
| 유니티 공부 | 직접 해 본 프로그래밍 공부, 유니티 기능 공부 |
| 개발 일지 | 직접 만드는 게임의 제작 기록 |
| 일상 | 그 밖의 이야기 |

헷갈릴 때 기준:

- **게임 개발 기술 vs 유니티 공부**: 남이 만든 기술이나 사례를 *조사해서 정리*하면 기술, 내가 *직접 따라 해 보며 배우면* 유니티 공부.
- **게임 개발 브리핑 vs 개발 일지**: 바깥 소식이면 브리핑, 내 게임 이야기면 개발 일지.

### 카테고리를 쓰는 법

글의 front matter에 위 표의 이름을 **띄어쓰기까지 똑같이** 적는다. 한 글자라도 다르면 다른 카테고리가 된다.

```yaml
categories: [유니티 공부]
```

### 카테고리를 추가하거나 순서를 바꿀 때

- 사이드바 순서는 `_data/sidebar_categories.yml`의 순서를 따른다.
- 사이드바에는 **글이 하나 이상 있는 카테고리만** 나온다. 빈 카테고리는 페이지가 없어서 링크가 깨지기 때문이다.
- 이름을 바꾸면 `_data/sidebar_categories.yml`과 이미 쓴 글들의 `categories:`도 같이 바꿔야 한다.

## 글 쓰는 법

`_posts/YYYY-MM-DD-영문-제목.md` 파일을 만든다.

```markdown
---
title: 글 제목
date: 2026-10-11 20:00:00 +0900
categories: [개발 일지]
tags: [유니티, 프로토타입]
---

본문
```

- 한 줄만 내리기: 문장 끝에 `<br>`
- 문단 나누기: 빈 줄 하나
- 글 제목에는 카테고리 접두어를 붙이지 않고 구체적인 내용만 쓴다. 카테고리는 `categories` 메타데이터로 표시한다. 정기 브리핑 PR 제목에는 검토 편의를 위해 카테고리 이름을 남긴다.

### 아직 안 올릴 글 (초안)

`_drafts/영문-제목.md`에 날짜 없이 만든다. `_drafts`는 사이트에 나오지 않는다. 올릴 때 `_posts/YYYY-MM-DD-영문-제목.md`로 옮기고 `date:`를 넣는다. 영문 제목 부분이 글 주소(`/posts/영문-제목/`)가 되니 옮길 때 바꾸지 않는다.

### 시리즈 글

여러 편으로 이어지는 글은 front matter에 같은 `series:` 이름을 적고, 본문 맨 위에 `{% include series.html %}` 한 줄을 넣는다. 같은 시리즈 글을 날짜순으로 모아 이전·다음 글과 전체 목차를 보여 준다. 목차에 보일 짧은 이름은 `series_title:`로 따로 적을 수 있다.

```yaml
series: 유니티 C# 일주일
series_title: "기초 Day 1: 스크립트와 변수"
```

- 시리즈 순서는 `date` 순서다. 앞 편보다 늦은 날짜로 올린다.
- 배포할 때 내부 링크 검사(htmlproofer)를 하므로, 아직 안 올린 글로 가는 링크가 있으면 배포가 실패한다. 서로 링크하는 글은 같이 올린다.
- 시리즈 전체에 붙일 안내(누가 썼는지 등)는 `_data/series.yml`에 시리즈 이름별 `note`로 적는다. 목차 상자 맨 위에 모든 글마다 나온다.
- 글마다 `description:`(한 줄 요약)을 꼭 적는다. 없으면 본문 첫 부분인 목차 상자 글자가 검색 요약과 홈 카드 미리보기에 대신 쓰인다.

### 글쓴이 표시

내가 쓰지 않은 글은 글쓴이를 밝힌다. `_data/authors.yml`에 있는 아이디를 front matter에 적는다.

```yaml
author: claude                 # AI가 쓴 글
authors: [hlcho426, claude]    # 내 이야기를 AI가 글로 옮긴 글
```

아무것도 안 쓰면 `_config.yml`의 `social.name`이 글쓴이로 나온다.

## 정기 브리핑 자동화

Codex 앱의 로컬 예약 작업으로 게임 개발·게임 개발 기술 데일리와 금요일 연구 큐레이션을 조사·작성하고 유형별 PR로 제출한다. 기술 데일리는 AI뿐 아니라 엔진·IDE·내러티브 테스트·아트 파이프라인을 다루며, 게임 제작의 구체적인 문제와 관련 있는 자료를 우선한다. 별도 유료 모델 API 키는 사용하지 않으며 Codex 구독 사용량을 소비한다. GitHub Actions는 빌드·링크 검사와 PR 미리보기를 맡는다. [설정·수동 테스트·실패 확인 안내](tools/briefing/OPERATIONS.md)를 따른다. 기존 ChatGPT 예약은 변경하지 않는다.

| `_data/contact.yml` | 사이드바 아래 아이콘 (트위터 숨김) |
| `_tabs/about.md` | 정보 페이지 |
