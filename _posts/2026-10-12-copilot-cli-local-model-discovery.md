반복적인 코드 탐색에 로컬 모델을 써 보고 싶어도 연결과 모델 선택이 번거로울 수 있다. Copilot CLI 업데이트는 실행 중인 로컬 제공자의 모델을 선택 메뉴에서 찾기 쉽게 한다. 모델 선택, 네트워크 사용, 작업 품질을 서로 다른 조건으로 살펴본다.

## 무슨 일이 있었나
{:.briefing-heading}

### 바뀐 기능 — 실행 중인 제공자의 모델을 고른다

GitHub는 Copilot CLI 1.0.94-0부터 로컬 모델을 발견하고 선택하는 기능을 안내한다. 실행 중인 Ollama의 모델을 /model 메뉴에서 고를 수 있고, 지원되는 제공자의 모델 목록·스트리밍과 연결 실패 설명도 소개한다. 로컬 모델을 자동 설치해 주는 기능으로 읽으면 안 된다.

### 사용 조건 — 모델을 로컬로 골라도 오프라인은 별도다

공식 글은 로컬 모델 선택이 오프라인 모드를 켜거나 GitHub 텔레메트리를 끄지 않는다고 명시한다. CLI의 오프라인 모드는 COPILOT_OFFLINE=true라는 별도 선택이며, 원격 제공자는 그 모드에서도 프롬프트와 코드 문맥을 받을 수 있다고 설명한다. 모델이 어디서 추론하는지와 어떤 연결이 열려 있는지는 따로 확인해야 한다.

## 왜 중요한가
{:.briefing-heading}

**분석:** 선택 메뉴가 편해졌다는 변화와 로컬 모델이 모든 코딩을 잘한다는 주장은 다르다. 도입 평가는 연결 성공, 결과 품질, 네트워크 동작을 각각 확인하는 쪽이 유용하다.

### 구체적인 작업 예시 — 작은 함수의 호출 위치 찾기

**설명용 예시:** 공개 시험 저장소에서 함수 이름과 ‘호출하는 파일과 줄을 찾아라’라는 요청을 준비한다. 기존 방식과 로컬 모델에 같은 범위의 파일을 주고 결과 위치가 맞는지 확인한다. 없는 호출을 만들거나 엉뚱한 파일을 지목하면 실패다.

이 작업은 실제 코드를 수정하지 않아 비교 결과를 확인하기 쉽다. 처리 시간뿐 아니라 틀린 위치를 사람이 확인한 시간도 기록한다. 외부 통신을 제한하려는 목적이라면 모델 선택 화면만 보지 말고 제공자와 관련 설정을 함께 검사해야 한다.

### 어떤 개발자에게 관련 있나 · 지금 도입할 만한가

**필자의 판단:** 이미 로컬 모델 실행 환경이 있고 반복 탐색을 비교하려는 CLI 사용자에게 관련 있다. 별도 하드웨어 구매보다 기존 환경에서 작은 읽기 작업을 시험할 후보이며, 복잡한 구현의 대체 품질은 별도 검증 대상이다.

## 개발에 적용할 점
{:.briefing-heading}

- 모델 제공자의 실행·연결 상태와 CLI 버전을 먼저 확인한다.

- 정답 위치가 알려진 읽기 과제로 결과·시간·재검토 비용을 비교한다.

- 오프라인이 목적이면 제공자 연결과 오프라인·텔레메트리 조건을 따로 확인한다.
