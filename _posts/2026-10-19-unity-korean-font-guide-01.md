> 이 글은 Unity 공식 자료와 설치된 패키지 소스를 확인해 정리한 실습 안내 초안이다. 메뉴는 Unity 6.6 계열(6000.6.0f1)의 uGUI에 포함된 TextMeshPro를 기준으로 확인했다. 버전에 따라 메뉴 위치와 표시가 조금 다를 수 있다.

<br>
게임 화면에 한글을 적었는데 `□□□`만 나온다.<br>폰트 파일을 넣었는데 어디에 연결해야 하는지도 모르겠다.
<br>
이 글은 그 지점부터 시작한다.<br>코드를 작성하지 않고 Unity에서 무엇을 눌러야 하는지 순서대로 따라간다.<br>이 과정에서 별도 에셋은 필요하지 않다.
<br>
**오늘은 먼저 1부만 따라 해서 한글 한 줄을 띄우면 된다.**<br>2부는 대사가 모였을 때, 3부는 번역과 출시를 준비할 때 돌아와 읽어도 된다.
<br>
| 순서 | 해 볼 일 | 끝났는지 확인하는 방법 |
|---|---|---|
| 1부 | 폰트를 넣고 크기와 간격 조절 | Game 화면에서 한글 문장이 보인다 |
| 2부 | 정해진 글자를 미리 굽기 | 준비한 문장이 Static 폰트로 표시된다 |
| 3부 | 번역·추가 대사·출시 관리 | 빠진 글자와 잘린 문장을 점검한다 |

## 먼저, 폰트 파일과 TMP 폰트는 다르다
{:.briefing-heading}
<br>
이 글에서 꼭 알아야 할 말은 네 개다.
<br>
| 이름 | 쉬운 뜻 |
|---|---|
| 원본 폰트 | 인터넷에서 받은 `.ttf`, `.otf` 파일. 글자 모양의 원본 |
| TMP 폰트 에셋 | TextMeshPro가 글자를 표시할 때 사용하는 Unity용 파일 |
| 아틀라스(Atlas) | 여러 글자 모양을 모아 담은 이미지 |
| 굽기(Bake) | 사용할 글자 모양을 아틀라스에 미리 준비하는 일 |
<br>
원본 폰트를 가져온 다음, 그 파일로 **TMP 폰트 에셋을 만들고 화면의 텍스트에 연결**한다.

이후에 나오는 **글리프(Glyph)**는 폰트가 그리는 글자 모양을 뜻한다. 문자는 ‘어떤 글자인가’를 나타내고, 글리프는 ‘그 글자를 어떤 모양으로 그리는가’에 가깝다. 다른 언어의 결합 문자나 합자까지 다루면 문자 하나와 글리프 하나가 항상 일대일로 대응하지는 않는다.

```text
원본 폰트(.ttf 또는 .otf)
        ↓ Unity에서 TMP 폰트 에셋 만들기
TMP 폰트 에셋(.asset)
        ↓ 화면의 글자에 연결
게임 화면에 한글 표시
```

이 글은 `Text - TextMeshPro`로 만드는 Canvas UI를 다룬다. UI Toolkit이나 3D 공간의 글자는 설정 화면이 다르므로 여기서는 섞지 않는다.

## 직접 해 보기
{:.briefing-heading}

### 1. 한글 폰트 파일 준비하기
<br>
먼저 **한글이 들어 있는 폰트 파일** 하나를 준비한다.
<br>
폰트 확장자에는 `.ttf`와 `.otf`가 있다. 확장자만으로 지원 여부나 품질을 판단할 수는 없다. 폰트의 내부 형식과 Unity·패키지 버전에 따라서도 결과가 달라질 수 있다.

이 실습에서는 선택지를 줄이기 위해 고정 굵기 `.ttf` 파일 하나를 사용한다.

처음에는 이름에 `Regular`가 있는 **고정 굵기 TTF 한 개**로 시작한다.<br>
여러 굵기가 하나에 들어 있는 가변 폰트나 여러 서체가 묶인 파일은 나중에 사용해도 된다.<br>
<br>
게임에 넣기 전에는 배포처의 라이선스를 읽는다.<br>
‘무료’라는 소개만 보지 말고 게임에 포함할 수 있는지와 필요한 고지 조건을 확인한다.<br>
받은 폰트와 함께 제공되는 라이선스 파일도 보관한다.<br>
Noto를 사용하는 경우에도 공식 저장소의 배포 파일과 동봉 조건을 확인한다.<br>
<br>
**폰트 라이선스 주의사항**

웹·문서에서의 사용과 게임에 포함해 배포하는 것은 이용 조건이 다를 수 있다. 소개 사이트에서 ‘상업용 무료’를 확인했더라도 최종적으로는 원배포처의 조건을 읽는다. 게임 배포 허용 여부, 변환·수정 조건과 고지 의무를 확인한다.

OFL(SIL Open Font License)은 조건을 지키면 상용 게임과 함께 폰트를 배포할 수 있는 라이선스다. 폰트를 포함해 배포할 때에는 해당 저작권 고지와 라이선스 전문도 제공해야 한다. 반드시 크레딧이나 설정 화면에만 넣어야 하는 것은 아니며, 사용자가 확인할 수 있는 별도 텍스트 파일 등의 방식도 허용한다. 실제 배포물에 포함됐는지까지 확인하자. [OFL 공식 원문](https://openfontlicense.org/open-font-license-official-text/)

### 2. Unity 안에 폴더 만들기
<br>
Unity의 재생 버튼이 꺼진 상태에서 시작한다.

1. 아래쪽 **Project** 창을 찾는다. 프로젝트의 파일이 보이는 창이다.
2. 왼쪽 폴더 목록에서 **Assets**를 클릭한다.
3. 오른쪽 빈 곳을 마우스 오른쪽 버튼으로 클릭한다.
4. `Create > Folder`를 누른다.
5. 폴더 이름을 `Fonts`로 입력한다.
6. `Fonts`를 더블클릭한다.
7. 탐색기에 있는 원본 폰트 파일을 Unity의 이 폴더 안으로 끌어 놓는다.

**확인할 것!**<br>
Project 창의 `Assets/Fonts` 안에 폰트 파일이 보이면 된다.<br>Windows에 폰트를 설치하는 것만으로는 프로젝트에 들어오지 않는다.
창이 보이지 않으면 상단 메뉴의 `Window > General > Project`로 다시 열 수 있다.<br>오른쪽 설정 창은 `Window > General > Inspector`다.

### 3. TMP 기본 리소스 가져오기

1. Unity 상단에서 `Window > TextMeshPro > Import TMP Essential Resources`를 누른다.
2. 가져오기 창이 열리면 `Import`를 누른다.
3. 작업이 끝날 때까지 기다린다.

이미 가져온 프로젝트라면 다시 할 필요는 없다. 예제 전체를 가져오는 `Examples & Extras`는 이 실습에 필요하지 않다.

### 4. 원본 폰트로 TMP 폰트 만들기

1. Project 창에서 방금 넣은 **원본 `.ttf` 또는 `.otf`** 파일을 한 번 클릭한다.
2. 선택된 상태에서 마우스 오른쪽 버튼을 누른다.
3. `Create > TextMeshPro > Font Asset > SDF`를 누른다.
4. 원본 옆에 이름이 `SDF`로 끝나는 폰트 에셋이 생겼는지 확인한다.

이전 버전에서는 메뉴가 `Create > TextMeshPro > Font Asset`에서 끝날 수도 있다. SDF는 글자 테두리까지의 거리 정보를 이미지에 담고, 셰이더가 그 정보로 테두리를 그리는 방식이다. 크기를 바꿔도 비교적 매끄럽게 표시할 수 있지만, 낮은 생성 품질의 글자를 무한히 확대해도 선명하다는 뜻은 아니다.

**확인:** 이제 파일이 두 종류다. 원본 폰트와, 화면에 연결할 TMP 폰트 에셋이다. 둘을 구분해 둔다.

### 5. 필요한 글자를 자동으로 준비하는 Dynamic 알아보기

**Dynamic(다이나믹)은 화면에 필요한 글자를 그때그때 준비하는 방식**이다.<br>여기서는 글자가 움직이거나 흔들린다는 뜻이 아니다.

원본 폰트에는 많은 글자의 모양이 들어 있다.<br>하지만 TMP가 화면에 표시하려면 그 모양을 앞에서 말한 **아틀라스, 즉 글자들을 모아 담는 이미지**에 준비해야 한다.<br>Dynamic은 이 준비를 자동으로 해 준다.

예를 들어 대사에 `안녕`이라고 적었다고 생각해 보자.

1. TMP가 `안`과 `녕`이 이미 아틀라스에 있는지 확인한다.
2. 없으면 원본 폰트에서 두 글자의 모양을 가져와 아틀라스에 추가한다.
3. 준비된 글자 모양을 사용해 화면에 `안녕`을 표시한다.
4. 나중에 대사를 `안녕 친구`로 바꾸면, 이미 있는 글자는 활용하고 새로 필요한 `친`, `구`도 같은 방식으로 준비한다.

이 과정에서 글자를 하나씩 생성하라는 버튼을 매번 누를 필요는 없다. <br>**대사를 고칠 때마다 사용할 글자 목록을 직접 다시 만들지 않아도 된다**는 것이 개발 중에 편한 이유다. <br>한 번 추가한 글자는 아틀라스에 남아 있는 동안 다시 사용할 수 있다.

반대로 **Static(스태틱)**은 사용할 글자를 미리 정해서 준비해 두는 방식이다.

| 방식 | 쉬운 설명 | 대사에 새 글자가 추가되면? |
|---|---|---|
| Dynamic | 필요한 글자를 그때그때 준비 | 원본에 그 글자가 있으면 자동으로 추가 시도 |
| Static | 정해 둔 글자를 미리 준비 | 미리 준비하지 않은 글자는 따로 추가하거나 다른 폰트의 도움을 받아야 함 |

지금은 게임의 대사를 계속 쓰고 고치는 단계이므로 **Dynamic으로 시작한다**. <br>Static으로 미리 준비하는 방법은 2부에서 따로 따라 한다.

다만 Dynamic도 **원본에 없는 글자를 만들어 주지는 않는다.** <br>영문만 들어 있는 폰트를 Dynamic으로 바꾼다고 한글이 생기지는 않는다. <br>지금 한글 원본 폰트를 준비하는 이유다.

#### 이제 Unity에서 Dynamic으로 설정하기

1. 아래쪽 Project 창에서 **방금 만든 SDF 에셋**을 클릭한다. 원본 `.ttf`나 `.otf`가 아니다.
2. 오른쪽 Inspector에서 `Generation Settings`를 펼친다.
3. `Atlas Population Mode`를 찾는다. 이름은 어렵지만 **글자 이미지를 어떤 방식으로 채울지** 고르는 항목이다.
4. 오른쪽 선택 메뉴를 눌러 `Dynamic`을 고른다. 이미 Dynamic이면 그대로 둔다.
5. 아래 표의 아틀라스 크기와 추가 이미지 설정도 확인한다.

| 설정 | 이번 실습 값 | 뜻 |
|---|---|---|
| Atlas Population Mode | Dynamic | 아직 없는 글자가 나오면 원본에서 추가 |
| Render Mode | SDFAA 유지| 글자 테두리 거리 정보를 기반으로 안티앨리어싱 적용 |
| Sampling Point Size | 생성값 확인 | 글자 이미지를 생성하는 크기. 화면의 Font Size와 다름 |
| Padding | 생성값 확인 | 글자 사이의 여유 공간이며 SDF 외곽선 효과에도 관계됨 |
| Atlas Width | 2048 | 글자 이미지 한 장의 가로 크기 |
| Atlas Height | 2048 | 글자 이미지 한 장의 세로 크기 |
| Multi Atlas Textures | 켜기 | 한 장이 차면 추가 이미지 사용 |

이 값은 **실습 시작값**이지 모든 게임의 정답은 아니다. Sampling Point Size와 Padding은 첫 실습에서는 생성된 값을 유지해도 된다.

Generation Settings에는 생성 결과를 보여 주는 항목도 있다. 설치한 패키지에서 생성 크기나 Padding이 읽기 전용이라면 Inspector에서 억지로 바꾸려 하지 않는다. 값을 비교하려면 2부의 Font Asset Creator에서 별도의 테스트 에셋을 생성한다. 그때 생성 크기 36, Padding 5를 비교 시작값으로 쓸 수 있다.

이미 글자를 넣어 쓰던 에셋의 아틀라스 크기나 생성 설정을 바꾸면 기존 데이터를 비우거나 재생성해야 할 수 있다. 운영 중인 폰트 대신 새 테스트 에셋으로 시작한다.

Dynamic은 계속 대사가 바뀌는 개발 중에 편하다. <br>대신 실행 중 글자 추가 비용이 있고 원본 폰트를 사용하므로 **원본 파일을 지우거나 Include Font Data를 끄지 않는다.** <br>Multi Atlas를 켰다고 메모리가 무제한으로 안전해지는 것도 아니다. [Unity의 Dynamic 폰트 설명](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/TextMeshPro/FontAssetsDynamicFonts.html)

#### 왜 2048로 시작할까? 크기만으로 정답을 정할 수는 없다

여기서 2048은 한글 실습을 위한 비교 시작값이다. 한글에 필요한 최소 크기나 모든 기기의 권장값이라는 뜻은 아니다. 필요한 문자가 적으면 작은 아틀라스로 충분할 수 있다.

현대 한글 완성형 음절은 11,172개지만, 모든 게임이 그 전부를 미리 담아야 하는 것은 아니다. 실제 UI·대사에 쓰는 문자와 닉네임처럼 입력 가능한 문자를 구분한다. 영문도 지원 언어가 늘면 악센트 문자 등 필요한 범위가 커진다.

| 바꾸는 설정 | 기대할 수 있는 변화 | 함께 확인할 것 |
|---|---|---|
| 아틀라스 한 변을 1024 → 2048로 확대 | 같은 생성 크기라면 더 많은 글자를 담을 공간 확보 | 같은 포맷에서 한 장의 픽셀 수는 4배 |
| Sampling Point Size 확대 | 복잡한 획의 형태를 더 자세히 담을 여지 확보 | 글자 하나의 면적이 커져 같은 장에 들어가는 수 감소 |
| Padding 확대 | SDF 거리 정보와 외곽선 효과를 위한 여유 확보 | 글자 사이 공간도 늘어 수용량 감소 |
| Multi Atlas 켜기 | 한 장이 부족하면 추가 장 생성 | 총 장수와 메모리, 실제 렌더링 비용 |

Sampling Point Size가 90이라고 항상 낭비인 것도, 36이라고 항상 충분한 것도 아니다. 작은 본문과 크게 확대되는 제목은 필요한 품질이 다르다. 반대로 큰 아틀라스로 바꾸기만 하고 생성 크기가 같다면 개별 글자의 세부 정보가 자동으로 늘지는 않는다.

TMP의 크기 선택지에는 512·1024·2048처럼 2의 거듭제곱이 쓰인다. 다만 Unity가 모든 텍스처에 이 크기를 강제하는 것은 아니다. 목표 기기에서 지원하는 최대 텍스처 크기와 메모리를 함께 확인한다. [Unity 텍스처 크기 설명](https://docs.unity3d.com/6000.0/Documentation/Manual/ImportingTextures.html)

**설치 파일 용량과 실행 중 메모리도 구분하자.** 공개 uGUI 소스의 일반 SDF 아틀라스는 Alpha8로 생성된다. 이를 ASTC·ETC2로 압축되는 일반 이미지처럼 가정하면 안 된다. Alpha8 한 장의 픽셀 데이터만 계산하면 1024²는 약 1 MiB, 2048²는 약 4 MiB, 4096²는 약 16 MiB다. 이는 밉맵·CPU 사본·기타 데이터를 제외한 계산 예시이며, 실제 기기의 사용량은 따로 측정해야 한다. 컬러 이모지 아틀라스는 포맷도 다르다. [공식 uGUI 소스](https://github.com/Unity-Technologies/uGUI/blob/main/com.unity.ugui/Runtime/TMP/TMP_FontAsset.cs)

추가 아틀라스나 다른 폰트의 재질을 함께 쓰면 그리기 작업이 나뉠 수 있다. 하지만 장수만으로 드로우콜 수나 메모리 파편화를 단정하지 않는다. 3부에서 실제 화면의 비용을 확인한다.

### 6. 화면에 텍스트 만들기

1. 왼쪽 **Hierarchy** 창의 빈 곳을 마우스 오른쪽 버튼으로 클릭한다.
2. `UI (Canvas) > Text - TextMeshPro`를 선택한다. 버전에 따라 `UI > Text - TextMeshPro`로 보일 수 있다.
3. `TMP Importer` 창이 나타나면 `Import TMP Essentials`를 누른다.
4. Hierarchy에 생긴 텍스트 오브젝트를 클릭한다.

Canvas가 없었다면 함께 만들어질 수 있다. Canvas는 화면 UI를 올려 두는 판이라고 생각하면 된다.

**`3D Object > Text - TextMeshPro`가 아니라 UI 쪽 메뉴를 사용한다.**

### 7. 한글 폰트 연결하기

1. 텍스트 오브젝트를 선택한 상태로 오른쪽 Inspector를 본다.
2. `TextMeshPro - Text (UI)` 컴포넌트를 찾는다.
3. `Text Input` 입력칸의 기존 문장을 지우고 아래 내용을 넣는다.

```text
안녕하세요! 한글 폰트 연결을 확인합니다.
가나다라마바사 아자차카타파하
0123456789 ABC abc !? … “인용문”
```
숫자, 영문을 제외한 한글이 `□□□`로 나온다.<br>
아래 내용을 추가로 설정한다.<br>

4. 같은 컴포넌트의 `Font Asset` 칸을 찾는다.
5. 아래쪽 Project 창에서 **SDF 에셋**을 이 칸으로 끌어 놓는다.
6. `Auto Size`가 켜져 있으면 우선 끈다.
7. `Font Size`를 `36`으로 입력한다.
8. 글자 색을 확인하고 어두운 배경이면 밝은 색으로 바꾼다.

`Font Asset`에 넣는 것은 원본 `.ttf`가 아니라 **SDF 에셋**이다. Inspector 위쪽의 자물쇠가 잠겨 있으면 선택을 바꿔도 다른 대상이 표시될 수 있으니 잠금도 확인한다.

### 8. 글자를 담는 상자 넓히기

글자는 폰트 크기와 별개로 **표시할 상자**가 필요하다.

텍스트 오브젝트에서 Inspector 맨 위의 `Rect Transform`을 펼친다. 기본 중앙 앵커 상태라면 다음 값을 넣는다.

| 항목 | 실습 값 |
|---|---|
| Pos X / Pos Y | 0 / 0 |
| Width | 900 |
| Height | 300 |
| Scale X / Y / Z | 1 / 1 / 1 |

위치·크기 항목이 `Left`, `Right`처럼 나온다면 앵커가 늘어나는 설정이다. `Rect Transform` 왼쪽의 작은 사각형 그림을 클릭하고 중앙에 모인 앵커를 선택하면 Width와 Height로 조절할 수 있다. 기존 게임 UI 대신 실습용 새 오브젝트에서 해 본다.

### 9. 화면 크기 기준 정하기

1. Hierarchy에서 **Canvas**를 클릭한다.
2. Inspector의 `Canvas Scaler`를 찾는다.
3. `UI Scale Mode`를 `Scale With Screen Size`로 바꾼다.
4. 가로 화면 실습이라면 `Reference Resolution`을 `1920 × 1080`으로 입력한다.
5. `Screen Match Mode`가 `Match Width Or Height`인지 확인하고 `Match`를 `0.5`로 둔다.

이 설정은 ‘1920×1080 화면을 기준으로 만든 UI를 다른 크기의 화면에 맞춰 조절한다’는 뜻이다. `0.5`는 가로와 세로를 함께 고려하는 실습 시작값이다. 세로 게임이라면 예를 들어 `1080 × 1920`처럼 화면 방향부터 바꿔 잡는다. [Canvas Scaler 공식 설명](https://docs.unity3d.com/Packages/com.unity.ugui%402.0/manual/script-CanvasScaler.html)

**기존 게임의 Canvas 설정을 이 실습 값으로 일괄 교체하지 않는다.** 여기서는 새 학습용 UI의 기준을 잡는 것이다.

QHD나 4K 화면을 지원하더라도 UI 배치의 기준은 1920×1080으로 잡을 수 있다. Reference Resolution은 실제 게임의 렌더링 해상도를 1920×1080으로 제한하는 설정이 아니다.

Canvas Scaler는 화면에 맞춰 UI 배율을 조절한다. 글자 선명도, 실제로 읽히는 크기, 다른 화면 비율에서의 배치까지 보장하지는 않는다. Game 화면의 해상도와 비율을 바꿔 보고, 최종 판단은 목표 기기에서 한다.

### 10. Game 화면에서 확인하기

1. 가운데 위쪽의 `Game` 탭을 클릭한다.
2. 해상도 선택 메뉴가 `Free Aspect`라면 펼쳐서 `1920×1080`을 선택한다. 없으면 `+`로 Fixed Resolution을 추가한다.
3. 화면 미리보기의 `Scale`이 축소되어 있는지도 확인한다.
4. 한글이 보이는지 확인한다. 정적인 UI 텍스트는 재생 전에도 보일 수 있다.
5. 상단 재생 버튼을 누른 뒤에도 표시되는지 확인하고 재생을 멈춘다.
6. `Ctrl+S`로 씬을 저장한다. 파일명은 예를 들어 `font_test`로 정한다.

**여기까지의 완료 기준은 한글·숫자·영문이 화면에 보이는 것**이다. 특수기호 일부만 □라면 원본 폰트에 그 기호가 없을 수 있다. 그때는 아래의 폴백을 확인한다.
폴백(Fallback Font Assets)은 주 폰트에 없는 글자를 보조 폰트에서 찾는 기능이다. 2부에서 연결해 본다. 컬러 이모지는 별도 설정이 있으므로 3부에서 구분한다.
지금은 여기서 멈춰도 된다. 이미 게임에서 한글을 표시하기 위한 첫 연결을 마쳤다.

## 글자 크기·자간·줄 간격은 어디에서 바꿀까?
{:.briefing-heading}
다시 Hierarchy에서 **텍스트 오브젝트**를 선택한다. 폰트 파일의 Inspector가 아니라 화면 글자의 Inspector를 열어야 한다.

| 바꾸고 싶은 것 | TextMeshPro 컴포넌트에서 찾을 항목 | 처음 해 볼 조작 |
|---|---|---|
| 글자 크기 | Font Size | 36 → 40으로 바꿔 비교 |
| 글자 사이 | Spacing Options의 Character | 0에서 시작해 조금씩 조절 |
| 단어 사이 | Word | 우선 0 유지 |
| 줄 사이 | Line | 0 → 5로 바꿔 비교 |
| 문단 사이 | Paragraph | 우선 0 유지 |
| 왼쪽·가운데 정렬 | Alignment | 문장 본문은 왼쪽부터 비교 |

이 숫자는 **체감하기 위한 예시**다. 특히 Line의 5는 워드프로세서의 ‘줄 간격 1.5배’와 같은 뜻이 아니다. 화면을 보며 변화를 확인한다. [TMP의 글자와 간격 설정](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/TextMeshPro/TMPObjectUIText.html)

### 크기 36이면 출시해도 될까?

`36`만으로 판단할 수 없다. 같은 36이어도 폰트 모양, Canvas 배율, 게임을 띄울 실제 화면에 따라 읽히는 크기가 달라진다.

제목·본문·버튼·작은 설명의 크기를 각각 정해 두고 재사용하는 편이 좋다. 예를 들어 본문을 읽기 편하게 맞춘 뒤, 제목은 더 크게, 보조 설명은 읽을 수 있는 범위에서 작게 만든다. 최소 크기는 실제 지원 기기에서 확인한다.

글자가 작다고 Transform의 Scale을 2로 늘리는 습관보다는 **Scale은 1로 두고 Font Size와 상자 크기부터 조절**하는 습관을 들이자.

### Auto Size는 처음에는 끄자

Auto Size는 정해진 상자에 맞도록 글자를 자동으로 키우거나 줄인다. 편하지만 긴 번역이 들어왔을 때 그 버튼만 유독 작아질 수 있다.

먼저 Auto Size를 끄고 크기와 상자를 정한다. 짧은 라벨 등 꼭 필요한 곳에서만 켜고 `Min`과 `Max`로 허용 범위를 정한다. 예를 들어 `Min 30 / Max 36`으로 비교해 볼 수 있지만, 이것도 출시 권장값은 아니다. 한글을 억지로 납작하게 넣지 않도록 `WD%`는 우선 0으로 둔다.

### 굵게, 외곽선, 그림자는 나중에

먼저 기본 글자가 잘 읽히게 만든다. 작은 한글에 굵게와 두꺼운 외곽선을 동시에 쓰면 `ㅁ`, `ㅂ`, `ㅎ`의 안쪽이 좁아질 수 있다.

강조용 Bold 원본이 있다면 같은 절차로 TMP 폰트를 따로 만들고 강조 텍스트에 연결해 비교한다. 본문용과 제목용의 재질 효과가 달라야 한다면 `Material Preset`을 따로 만들어 사용한다. 공용 재질 하나를 바꾸면 그것을 쓰는 다른 글자까지 바뀔 수 있다.
