스크립트를 고칠 때마다 기다리는 시간이 줄어들까. Unity의 10월 5일 공식 설명은 Unity 7 첫 알파의 CoreCLR 전환을 공개했지만, 반복 작업 속도 개선을 이미 달성했다고 보고하지는 않았다. 지금 읽어야 할 핵심은 새로운 재로딩 방식과 호환성 시험의 범위다.

## 무슨 일이 있었나
{:.briefing-heading}

### 현재 알파에서 바뀐 실행 기반

CoreCLR은 C# 코드를 실행하는 .NET 런타임이다. Unity는 첫 7.0 알파 에디터에서 Mono를 대체했다고 설명했다. 다만 이 알파의 언어·API 범위는 C# 9와 .NET Standard 2.1이며, C# 14와 .NET 10의 공개 시점은 확정하지 않았다. 공식 글은 제작용 사용보다 프로젝트 호환성 시험을 권한다.

### 재로딩은 남고 성능 개선은 후속 작업이다

10월 6일 담당자 답변에 따르면 에디터는 ALC, 즉 어셈블리를 관리하는 AssemblyLoadContext 기반으로 코드 재로딩을 수행한다. 진행 표시 문구에는 예전 표현이 남아 있을 수 있다. 담당자는 현재 목표를 성능 동등성으로 설명했고, 즉각적인 코드 반영 데모를 지금 알파에서 기대할 기능으로 보지 말라고 밝혔다. 발표에는 동일 프로젝트의 작업 대기시간을 비교한 수치가 없다.

### 제작 작업은 어떻게 달라지나

기존에 어려웠던 일은 코드 한 줄을 바꾼 뒤 반복 시험을 재개하기까지 기다리고, 버전 변경 후 같은 동작이 유지되는지 확인하는 과정이다. 이번 변화는 그 가운데 코드를 다시 불러오는 엔진 내부 단계에 있다. 편집자의 제안은 ‘업그레이드하면 빨라진다’고 전제하지 않고, 수정→컴파일→재로딩→상태 확인→조작 재개를 나눠 관찰하는 것이다.

### 구체적인 작업 예시

다음은 실제 실행 결과가 아닌 편집자의 설명용 예시다. 입력으로 버튼을 누르면 카운터가 증가하는 작은 샘플과 표시 문구만 바꾼 스크립트를 준비한다. 처리는 저장 후 에디터가 코드를 다시 불러오게 하고, 같은 버튼을 같은 순서로 누르는 것이다. 기대 결과는 수정한 문구가 보이고 카운터가 정해 둔 초기화·증가 규칙을 유지하는 상태다. 버튼 반응이 중복되거나 예외가 나오거나 이전과 다른 초기값이 나타나면 실패로 기록한다. 조작 재개까지의 시간도 따로 적되, 여기서는 어떤 초 단위 결과도 얻었다고 주장하지 않는다.

### 실제 사용 조건

AI 생성 도구의 발표가 아니라 엔진의 실행 기반 변경이다. 공식 글은 Hub의 Pre-releases에서 첫 알파를 제공한다고 설명한다. 알파 시험에는 원본을 보존한 복사본과 재현 가능한 샘플을 준비하는 편이 적절하다. 모든 패키지·플랫폼에서 호환된다는 확인은 없다.

### 확인된 범위와 한계

공식 발표와 담당자 설명은 독립 측정이 아니다. 새 재로딩 방식이 실제 작업에서 얼마나 빨라지는지는 이번 조사로 확인하지 못했다. 이후 빌드의 변화도 시험해야 하며, 최신 언어·API 지원 계획을 첫 알파에 모두 적용된 것으로 읽으면 안 된다.

## 왜 중요한가
{:.briefing-heading}

**분석:** 반복 제작에서 중요한 것은 대기창의 이름보다 수정 후 다시 시험할 수 있을 때까지의 시간이다. 실행 기반의 교체는 장기적인 개선 토대가 될 수 있지만, 그 자체가 오늘의 작업시간 절약을 입증하지는 않는다. 따라서 편집자의 판단은 속도와 호환성을 별도 항목으로 기록하는 것이다. 오류 없이 열렸다는 관찰과 저장 데이터·재실행 동작이 유지된다는 검증도 구분해야 한다.

### 어떤 개발자에게 관련 있나

Unity 에디터 확장이나 패키지를 유지보수하는 개발자, 버전 이전을 준비하는 프로그래머에게 관련 있다. 비교 가능한 샘플과 기존 동작 기준을 확보한 경우에 의미 있는 시험을 할 수 있다.

### 지금 도입할 만한가

판단은 호환성 시험, 제작 적용은 보류다. 복사본에서 재로딩과 상태 유지 문제를 먼저 찾을 수는 있지만, 성능 이득이나 안정성을 이번 자료로 확정할 수 없다. 기존 작업의 대기시간만 줄이려는 개발자는 후속 빌드와 실제 비교 기록을 관찰할 이유가 더 크다.

## 개발에 적용할 점
{:.briefing-heading}

- 설명용 시험 제안: 작은 공개 샘플의 복사본을 같은 기기에서 기존 버전과 알파로 열고, 패키지 버전·Play Mode 설정·변경한 코드 범위를 기록해 비교 조건을 맞춘다.

- 스크립트 저장부터 컴파일·재로딩이 끝나 다시 조작 가능한 시점까지를 같은 방법으로 반복 측정한다. 첫 가져오기 시간과 이후 반복 시간을 분리하고, 평균만으로 멈춤이나 오류를 숨기지 않는다.

- 저장 후 재실행과 같은 조작의 반복을 확인한다. 컴파일 오류, 상태 중복, 예외 또는 기존 데이터의 변화가 나타나면 성능 판단을 멈추고 작은 재현 사례로 줄인다.
