대화 내용을 고친 뒤 선택지와 변수 변화까지 다시 검사하는 일은 반복된다. Yarn Spinner의 9월 보고서는 파일 기반 테스트의 토대와 비동기 실행, 화면 연출 명령의 개발 상황을 소개한다. 과거 보고서의 계획과 공개 릴리스를 나눠 읽는다.

## 무슨 일이 있었나
{:.briefing-heading}

### TestPlans — 진행과 기대 내용을 파일로 표현

개발팀은 TestPlans라는 하위 시스템을 추가했다고 설명한다. 파일로 대화 진행을 지시하거나 기대한 내용과 비교하는 기반이다. 완성된 자동 플레이테스트 제품이 모든 대화를 검증한다고 발표한 것은 아니다.

### Unity 3.3 — 실행 부분을 다시 구성

9월 30일 보고서에서는 Unity용 VM 재작성을 마치고 시험 중이며 10월 3.3 제공을 목표로 설명했다. VM은 대화 스크립트를 실제 진행하는 실행 부분이다. 사용자 정의 함수와 취소 가능한 명령이 새 구조의 활용 대상으로 소개된다. 확인한 공개 GitHub 릴리스 목록의 Latest 표시는 v3.2.8이므로 개발 계획을 정식 출시로 소개하지 않는다.

### Visual Novel Kit — 연출 명령의 개발 재개

화면의 배경·인물·효과를 미리 정의한 명령으로 다루는 애드온도 다시 개발 중이라고 안내한다. 공식 예시에는 인물의 표정과 위치를 지정하는 show 명령이 있다. 각 구성의 이용·배포 조건과 프로젝트 호환성은 별도 확인 대상이다.

## 왜 중요한가
{:.briefing-heading}

**분석:** 대사를 추가하는 속도만큼 수정 뒤 상태를 확인하는 과정도 중요하다. 대화와 기대 결과를 함께 작성하면 반복 확인할 항목을 찾기 쉽다. 그러나 어떤 파일 형식과 검사 기능이 실제 제공되는지는 문서와 설치 버전에서 확인해야 한다.

### 구체적인 작업 예시 — 선택 후 변수와 다음 대화

**필자의 가상 시험 설계다. 아래 표는 실제 TestPlans 문법이 아니다.** 인사 선택에 따라 다음 대사가 달라지는 짧은 대화를 준비한다고 하자.

| 진행 | 기대할 검사 |
|---|---|
| 선택지 A를 고름 | 지정한 변수와 다음 대사 ID |
| 선택지 B를 고름 | A와 다른 결과, 이전 상태 잔존 여부 |
| 완료한 대화에 다시 접근 | 중복 이벤트 발생 여부 |

연출에서는 말풍선·인물 표시가 끝나기 전에 취소했을 때 다음 진행이 어떻게 되는지도 점검할 수 있다. 단, 이 시험은 자신이 사용하는 버전과 명령의 지원 범위를 먼저 확인한 뒤 구현해야 한다.

### 어떤 개발자에게 관련 있나 · 지금 도입할 만한가

**필자의 판단:** 대화 수정이 잦거나 조건·연출을 함께 관리하는 작업자에게 관련 있다. 개발 브랜치를 진행 중 프로젝트에 바로 넣기보다, 현재 안정 버전에서 기대 상태를 정리하고 별도 예제로 새 실행 구조를 시험할 후보로 본다.

## 개발에 적용할 점
{:.briefing-heading}

- 대화 한 장면에 선택·변수 변화·다음 대사를 함께 적는다.

- 공식 릴리스와 문서를 확인한 뒤 지원되는 테스트 형식으로 옮긴다.

- 실행 구조 변경은 복제 예제에서 취소·재시작·연출 종료 조건을 확인한다.
