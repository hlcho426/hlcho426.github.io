## 어떻게 만들었나?
{:.briefing-heading}

[유니티 C# 일주일](https://hlcho426.github.io/unity-csharp-week/) 앱은 Claude와 대화하면서 만들었다.<br>
코드는 한 줄도 직접 안 짰다.<br>
대신 풀어 보면서 불편한 점을 계속 말했다.<br>
그 피드백이 쌓여서 지금 모양이 됐다.<br>

## 첫 버전: 읽고, 풀고, 해가 뜬다
{:.briefing-heading}

처음 클로드가 만들어준 앱은 7일짜리 기초 코스였다.<br>
설명을 읽고, 바로 객관식 문제를 푸는 방식이다.<br>
스크립트의 생김새부터 변수, if, 반복문, 함수, Transform, 입력, 그리고 마지막 날에는 코인 줍기 미니 프로젝트까지.<br>

받은 앱은 이런 구조였다.<br>

- 하루(Day)에 레슨 3개
- 레슨 하나 = 짧은 설명 → 객관식 문제 몇 개
- 레슨을 끝낼 때마다 수평선 위로 해가 조금씩 떠오른다

## 다 풀었으니 다음 코스
{:.briefing-heading}

기초를 생각보다 빨리 끝냈다.<br>
![Claude에게 다음 코스 요청](/assets/img/unitystudy/csharp_make_image01.png){: w="1174" h="957" }

다음 코스를 부탁했고, 그걸 끝내면 또 다음 코스를 부탁했다.<br>
그렇게 기초 → 심화 → 실전 → 다지기 → 시스템까지 다섯 코스가 됐다.<br>

- **심화**: 클래스와 객체, 코루틴, 프리팹, 상태 머신, 이벤트, ScriptableObject, 세이브
- **실전**: 상속, 인터페이스, 람다, 싱글톤, 애니메이션과 UI, 새 Input System, 디버깅
- **다지기**: List, Dictionary, null, 실행 순서를 원리부터 다시
- **시스템**: Addressables와 외부 데이터 테이블

![Claude가 만들어준 유니티 공부 앱](/assets/img/unitystudy/csharp_make_image02.png){: w="1174" h="957" }

지금 앱을 다시 보면 코스마다 조금씩 다르다.<br>
처음 만든 기초·심화 레슨에는 힌트 버튼이 없고, 실전부터 생긴다.<br>
앱이 나랑 같이 자란 흔적이다.<br>

재미있었던 건, 내가 중간에 따로 물어본 질문이 다음 레슨에 그대로 들어갔다는 것이다.<br>
void는 왜 쓰는지 물어봤고<br>
![Claude에게 void 질문](/assets/img/unitystudy/csharp_make_image03.png){: w="1174" h="957" }
나중에 세이브 레슨에서 이렇게 나왔다.<br>

> Save는 일만 하니 void, Load는 꺼내서 돌려주니 SaveData.

내 질문이 문제가 돼서 돌아오니까 확실히 머리에 남았다.<br>

## 피드백 1: 눈으로만 보니까 안 들어온다
{:.briefing-heading}

객관식은 금방 익숙해졌다.<br>
보기 네 개 중에 이상한 걸 지우다 보면 답이 보인다.<br>
그런데 코드를 직접 쓰라고 하면 못 쓸 것 같았다.<br>

그래서 듀오링고처럼 블록을 조립하는 문제를 넣어 달라고 했다.<br>
![Claude에게 듀오링고의 블록 조립 기능 요청](/assets/img/unitystudy/csharp_make_image04.png){: w="1146" h="843" }

블록 조립은 다지기 코스부터 들어갔다.<br>
![Claude에게 듀오링고의 블록 조립 기능 요청](/assets/img/unitystudy/csharp_make_image05.png){: w="1146" h="843" }

```
[ rb ]  [ = ]  [ GetComponent<Rigidbody>(); ]  [ Rigidbody ]  [ new ]
```

이런 블록들을 눌러서 `rb = GetComponent<Rigidbody>();` 한 줄을 만든다.<br>
`Rigidbody`나 `new` 같은 함정 블록이 섞여 있어서, 왜 자료형을 다시 쓰면 안 되는지 알아야 맞힐 수 있다.<br>
여러 줄짜리는 줄 하나가 블록 하나다. 함수 전체를 한 줄씩 순서대로 쌓는다.<br>

객관식으로 볼 때는 다 아는 것 같았는데, 블록으로 조립하니까 순서를 헷갈렸다.<br>
모르는 걸 알게 해 주는 게 블록 조립의 진짜 역할이었다.<br>

## 피드백 2: 페이지가 뚝뚝 끊어진다
{:.briefing-heading}

폰 화면은 작다.<br>
설명 화면에서 코드를 보여 주고, 다음 화면에서 "위 코드의 출력은?" 하고 묻는데, 다음 화면에는 그 코드가 없다.<br>
기억에 의존해서 풀어야 했다.<br>
![Claude에게 앞 설명 다시보기 기능 요청](/assets/img/unitystudy/csharp_make_image06.png){: w="1209" h="1189" }
_Claude에게 앞 설명 다시보기 기능을 요청하던 대화_
이걸 말했더니 두 가지가 생겼다.<br>

- 문제 화면 오른쪽 위의 **📖 앞 설명 다시 보기** 버튼. 누르면 이 레슨에서 지금까지 본 설명이 다 나온다.
- "위 ~"로 시작하는 문제는 **앞 설명의 코드를 문제 화면에 같이** 보여 준다.

작은 기능인데, 폰으로 공부할 때는 이게 제일 컸다.<br>

## 그리고 이번에: 하나의 링크로, 정리해서
{:.briefing-heading}

여행에서 돌아와서 이 앱을 다른 사람도 쓸 수 있게 정리하기로 했다.<br>
Claude Code에게 맡겼다. 내가 원하는 걸 말하면 Claude가 작업하고, 나는 결과를 보고 정했다.<br>

원래 앱은 HTML 파일 하나에 디자인, 앱 코드, 레슨 105개가 전부 섞여 있었다.<br>
문제 하나 고치려고 해도 2,500줄이 넘는 파일을 뒤져야 했다.<br>

그래서 시스템 코스에서 배운 "데이터와 코드 분리"를 그대로 적용해 달라고 했다.<br>

- 레슨 내용은 코스별 데이터 파일(`basic.json`, `adv.json` …)로
- 앱 코드는 따로
- 코스 목록도 설정 파일 하나로

Claude는 옮기고 나서 원본과 한 글자도 다르지 않은지 검증까지 했다.<br>
데이터를 고칠 때마다 돌릴 수 있는 검사 스크립트도 만들어 줬다.<br>
레슨 id가 겹치지 않는지, 객관식 정답 번호가 보기 범위 안에 있는지, 블록 조립 정답을 주어진 블록으로 정말 만들 수 있는지를 확인한다.<br>

그 밖에 바뀐 것.<br>

- GitHub Pages에 올려서 **링크 하나로** 누구나 들어올 수 있게
- 홈 화면에 설치하고, 한 번 열면 **인터넷 없이도** 열리게
- 배우는 순서에 맞게 레슨 위치를 조금 옮겼다. "변수의 범위와 함수의 흐름"은 기초 마지막 날로, "값 형식과 참조 형식"은 심화 마지막 날로.

## AI가 만든 문제도 틀릴 수 있다
{:.briefing-heading}

정리하면서 Claude가 레슨 105개를 처음부터 다시 검토했다.<br>
대부분 정확했지만 고쳐야 할 곳도 있었다.<br>

예를 들어 실전 코스에 "코인을 `Destroy`한 다음 줄에서 코인 위치를 읽으면 무슨 에러가 날까?"라는 문제가 있었다.<br>
앱의 정답은 `MissingReferenceException`이었다.<br>
그런데 유니티 공식 문서를 보면 `Destroy`는 그 자리에서 바로 지우지 않고, 이번 프레임의 Update가 다 끝난 뒤에 지운다.<br>
그러니 같은 프레임의 바로 다음 줄에서는 에러가 안 난다.<br>
그래서 문제를 "다음 프레임에 읽으면"으로 고치고, 해설에 이 차이를 적어 두었다.<br>

이런 식으로 코드가 실제로는 컴파일이 안 되는 곳, 에디터와 빌드에서 에러 이름이 다른 곳, 레슨을 옮기면서 "Day 3에서 배운~"이 엉뚱한 날을 가리키게 된 곳까지 고쳤다.<br>

공부하는 사람 입장에서는 "AI가 만든 문제니까 맞겠지"가 제일 위험하다.<br>
