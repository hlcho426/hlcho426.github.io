> 이 글은 Unity 공식 자료와 설치된 패키지 소스를 확인해 정리한 실습 안내 초안이다. 메뉴는 Unity 6.6 계열(6000.6.0f1)의 uGUI에 포함된 TextMeshPro를 기준으로 확인했다. 버전에 따라 메뉴 위치와 표시가 조금 다를 수 있다.


## 3부. 계속 만드는 동안 지켜 두면 편한 것
{:.briefing-heading}

### 같은 폰트를 매번 새로 만들지 않기

화면마다 SDF 에셋을 새로 만들 필요는 없다. 같은 본문용 폰트 에셋을 여러 텍스트가 함께 사용하면 된다.

폰트를 바꿀 때는 기존 에셋을 지우고 같은 이름으로 다시 만드는 방식보다 기존 에셋을 갱신하는 편이 좋다. Unity는 이름뿐 아니라 파일의 고유 식별자로 참조하므로, 새로 만들면 연결이 끊길 수 있다. 이미 배치한 폰트를 갱신할 때는 기존 에셋의 Inspector 메뉴에서 `Update Atlas Texture...`를 사용하고 원본 파일·문자 목록·설정을 확인한 뒤 저장한다. 변경 전 버전 관리도 남긴다.

### 폴더와 파일을 함께 관리하기

최소한 다음 자료를 보관한다.

- 원본 폰트와 라이선스 파일
- TMP 폰트 에셋, 재질, 생성된 아틀라스
- 미리 굽는 데 사용한 문자 파일
- Unity가 만든 `.meta` 파일
- 굽기 설정과 확인한 Unity 버전

파일 정리는 Unity Project 창에서 한다. 특히 `.meta`를 버리고 복사하면 연결이 달라질 수 있다. Dynamic 폰트의 원본은 출시 빌드에서도 필요하다.

### 모든 폰트를 Resources에 몰아넣지 않기

위 실습처럼 직접 참조할 폰트는 `Assets/Fonts` 등 프로젝트 폴더에서 관리할 수 있다. 이름으로 찾는 특별한 사용법이 있을 때 해당 검색 경로를 따로 설정한다. ‘빌드에 안 들어갈까 봐’라는 이유로 원본 폰트 전부를 Resources에 넣지 않는다.

### 기본 폰트만 바꾸고 끝내지 않기

Project 창에서 `TMP Settings`를 검색하고 `Default Font Asset`을 지정하면 새 텍스트를 만들 때 도움이 된다. 하지만 **이미 다른 폰트가 지정된 UI까지 모두 교체되지는 않는다.**

본문뿐 아니라 버튼, 입력칸, 입력칸의 안내 문구, 선택지, 팝업, 로딩 화면도 확인한다. 자주 쓰는 버튼과 텍스트는 프리팹으로 만들어 재사용하면 빠뜨리는 곳을 줄일 수 있다.

### 공통으로 사용할 보조 폰트는 전역 폴백에 등록하기

`TMP Settings`의 **Fallback Font Assets**에는 여러 TMP 텍스트가 공통으로 검색할 보조 폰트를 등록할 수 있다. 에셋별 폴백과 전역 폴백은 검색 순서가 있으므로, 모든 텍스트를 이 폰트로 교체하는 기능은 아니다. 목록에 폰트를 추가할 때에는 기호의 모양·높이·간격이 본문과 어울리는지도 확인한다. [TMP 폴백 검색 순서](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/TextMeshPro/FontAssetsFallback.html)

### 컬러 이모지는 일반 SDF 폴백과 구분하기

한글 SDF 폰트나 일반 폴백 목록만으로 모든 이모지가 해결되지는 않는다. uGUI 2.0 공식 문서는 컬러 이모지를 포함한 원본으로 `Create > TextMeshPro > Font Asset > Color`에서 에셋을 만들고, TMP Settings의 **Fallback Emoji Text Assets**에 등록하는 절차를 안내한다. 문서·버전에 따라 메뉴가 `FontAsset`으로 표기될 수 있다.

텍스트 컴포넌트의 **Emoji Fallback Support**는 이모지로 분류된 문자를 어느 목록에서 먼저 찾는지에 영향을 준다. 프로젝트의 설치 버전에서 해당 항목과 지원하는 원본 형식을 확인한다. 조합 이모지까지 모두 지원한다고 가정하지 말고, 게임에서 허용할 이모지를 정해 실제 기기에서 시험한다. 이모지가 필요 없는 게임이라면 이 설정을 추가할 필요는 없다. [공식 컬러 이모지 안내](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/TextMeshPro/ColorEmojis.html)

## 번역을 넣을 때 폰트도 다시 확인하기

한국어 한 문장을 잘 표시했다고 다른 언어도 준비된 것은 아니다.

예를 들어 ‘설정’ 버튼이 다른 언어에서 더 길어지면 글자가 줄거나 잘릴 수 있다. 버튼 상자에 충분한 공간을 주고, 여러 줄 허용 여부와 넘칠 때의 처리 방식을 미리 정한다. 문장마다 수동 줄바꿈을 잔뜩 넣으면 화면 크기가 바뀔 때 다시 손봐야 한다.

지원 언어가 늘어나면 다음을 확인한다.

1. **그 언어의 글자가 있는가?** 글리프 누락! 한국어 폰트가 일본어·중국어의 모든 글자를 지원한다고 가정하지 않는다.
2. **언어를 바꾸면 사용할 폰트도 바뀌는가?** 언어별 폰트를 연결할 수 있게 구성한다.
3. **줄이 바뀌어도 읽기 좋은가?** 마침표(`.`), 닫는 괄호(`)`), 물음표(`?`)가 다음 줄 맨 앞에 혼자 덜렁 떨어져 있지 않은지 확인한다. (이를 **'금칙 처리'**라고 부른다. TextMeshPro의 `TMP Settings > Line Breaking Rules`에서 행두/행미 금칙 규칙을 지정할 수 있다.)
4. **언어 전환 후에도 맞는가?** 버튼·팝업·입력칸까지 다시 확인한다.
5. **글자 표시 이상의 처리가 필요한가?** 아랍어 등의 문자 연결과 쓰기 방향은 폰트 파일 추가만으로 해결됐다고 보지 않는다.

번역이 아직 없다면 긴 임시 문장으로 공간을 시험한다. ‘기존 문장을 약 1.5배로 늘려 보기’ 같은 방법은 초기 스트레스 테스트일 뿐, 실제 번역 검사를 대신하지 않는다. Unity Localization에는 문장을 늘리거나 바꿔 시험하는 [의사 현지화 기능](https://docs.unity.cn/Packages/com.unity.localization%401.3/manual/Pseudo-Localization.html)도 있다. 이 글을 따라 하려고 해당 패키지까지 설치할 필요는 없다.

## 닉네임·채팅이 있는 게임은 무엇이 다를까?

대사와 UI는 미리 모을 수 있지만 플레이어가 입력할 글자는 전부 예측하기 어렵다. 이 경우에는 **어떤 언어와 문자를 지원할지 정한 Dynamic 폰트**가 필요할 수 있다.

입력칸에서는 완성된 닉네임뿐 아니라 입력 중 보이는 `ㄱ`, `ㅏ`, `ㅋㅋ`, `ㅠㅠ`도 확인한다. 이모지 전체를 일반 한글 폰트 하나로 표시할 수 있다고 가정하지 않는다. 글자 수 제한도 실제 입력 화면에서 확인한다.

반대로 닉네임과 채팅이 없는 게임이라면 이 문제까지 처음부터 모두 해결하려고 할 필요는 없다.

## 직접 해 보기

### 출시 전에는 에디터 밖에서 확인하기

에디터에서 잘 보인다는 것과 실제 출시 파일에서 잘 보인다는 것은 다르다.

Unity 6에서 테스트 빌드를 만드는 기본 경로는 다음과 같다.

1. 테스트 씬을 저장한다.
2. `File > Build Profiles`를 연다. 이전 버전에서는 `Build Settings`다.
3. 목표 플랫폼의 프로필과 씬 목록을 확인한다.
4. 필요한 경우 `Add Open Scenes`로 현재 테스트 씬을 넣는다.
5. `Build And Run`으로 실행 파일을 만들어 실행한다.

플랫폼 모듈이 없으면 설치가 필요할 수 있다. 실제 게임 프로젝트에서는 기존 씬 목록을 임의로 덮어쓰지 않는다. 먼저 작은 실습 프로젝트에서 확인해도 된다.

출시 대상 기기에서 다음 목록을 확인한다.

- [ ] 한글·영문·숫자·문장부호가 빠지지 않는다.
- [ ] 모든 지원 언어의 실제 문자열을 검사했다.
- [ ] 긴 대사, 긴 아이템 이름, 가장 큰 숫자도 잘리지 않는다.
- [ ] 최소 지원 화면에서도 본문과 버튼을 읽을 수 있다.
- [ ] 작은 글자에서 받침과 `ㅁ`, `ㅂ`, `ㅎ`의 내부가 구분된다.
- [ ] 밝은 장면과 어두운 장면에서 모두 읽힌다.
- [ ] 처음 등장하는 글자가 많은 화면에서도 눈에 띄는 멈춤이 없다.
- [ ] 언어를 여러 번 바꾼 뒤 폰트 이미지 장수와 메모리를 확인했다.
- [ ] 닉네임이 있다면 실제 기기의 한글 입력을 확인했다.
- [ ] 라이선스 파일과 필요한 고지를 포함했다.

성능이 의심되면 `Window > Analysis > Profiler`에서 실제 기기에 연결해 확인한다. 아틀라스 크기나 폰트 수를 늘렸다면 Memory와 렌더링 비용을 다시 본다. Multi Atlas나 폴백을 켰다는 것만으로 성능 검사를 통과한 것은 아니다.

### 처음 표시할 때와 다시 표시할 때 비교하기

다음은 측정 절차 예시다. 특정 기기에서 성능 개선을 확인했다는 결과는 아니다.

1. 실제 게임의 문장 중 처음 보는 글자가 많이 나오는 화면 하나를 고른다. 같은 기기·빌드·언어·문장·폰트 설정으로 비교한다.
2. 테스트용 Dynamic 에셋에 이미 글자가 들어 있는지 확인한다. `Clear Dynamic Data On Build`를 지원하는 버전이라면 설정도 기록한다. 재실행만으로 에디터에서 미리 채운 글자가 모두 사라진다고 가정하지 않는다.
3. Development Build에 Profiler를 연결하고 그 화면을 처음 열 때 CPU 프레임 시간, 아틀라스 장수, 텍스처 메모리를 기록한다. 화면을 닫았다가 같은 문장으로 다시 열어 비교한다.
4. CPU Usage의 Timeline에서 느린 프레임에 폰트 글리프 추가·텍스트 생성 작업이 있는지 확인한다. 폰트 작업과 이미지 로딩, 레이아웃·Canvas 갱신 비용을 구분한다.
5. 필요한 문자를 담은 Static 구성과 비교한다. Dynamic을 유지한다면 필요한 글자를 로딩 중 미리 추가하는 방법도 검토한다. 사전 추가는 비용을 로딩 구간으로 옮기는 방법이며, 원본에 없는 문자나 메모리 부족을 해결하지는 않는다.

| 기록할 항목 | 확인 목적 |
|---|---|
| 기기·OS·Unity·uGUI 버전, 빌드 설정 | 같은 조건으로 다시 비교하기 |
| 원본·문자 집합·생성 크기·Padding·아틀라스 크기 | 설정 변경에 따른 차이 구분하기 |
| 첫 표시와 재표시의 CPU 프레임 시간 | 최초 글리프 생성이 지연에 관계되는지 확인하기 |
| 사용 전후 아틀라스 장수·메모리 | Multi Atlas와 언어 전환 후 증가량 확인하기 |
| Batches·SetPass 등 렌더링 지표 | 폴백·재질을 늘린 뒤 그리기 비용 확인하기 |
| 최종 배포 빌드의 크기와 화면 품질 | 실행 중 메모리와 설치 파일 용량 구분하기 |

전체 텍스처 메모리에는 다른 이미지도 포함된다. 폰트별 사용량을 분리해야 한다면 Memory Profiler 등의 도구로 해당 텍스처를 확인한다. 렌더링 작업이 나뉘는 이유는 Frame Debugger로 살펴볼 수 있다. 개발 빌드의 측정값에는 진단 기능의 비용도 있으므로 최종 배포 빌드에서 체감과 표시 결과를 다시 확인한다.

### 대사나 번역이 바뀌었을 때 다시 검사하기

대사나 번역이 바뀐 업데이트에서도 문자 파일과 누락 검사를 다시 돌린다. **출시용 폰트는 한 번 굽고 잊는 파일이 아니라, 게임의 문장과 함께 관리하는 리소스**다.

관리 순서는 `문자열 추출 → 문자 파일 갱신 → Static 재생성 → 누락 검사 → 대표 화면 빌드 확인`으로 정해 두면 좋다. 팀 규모가 커지면 이 중 문자열 추출과 누락 검사를 에디터 도구나 빌드 전 검사로 자동화할 수 있다. 주 Static 폰트 자체의 누락과 허용한 폴백까지 포함한 표시 가능 여부를 따로 보고하도록 만든다.

## 막혔을 때는 여기부터 확인하기

| 증상 | 먼저 할 일 |
|---|---|
| 원본은 넣었는데 한글이 □다 | 텍스트의 Font Asset 슬롯에 한글 SDF를 연결했는지 확인 |
| SDF 생성 메뉴가 없거나 실패한다 | 원본 폰트를 선택했는지, TMP Essentials를 가져왔는지, Console 오류 확인 |
| Dynamic 생성 시 원본을 못 읽는다 | 원본 폰트 Inspector의 Include Font Data 확인. 변경했다면 Apply |
| 폰트는 맞는데 일부 글자만 □다 | 원본 지원 문자, Static 문자 목록, 아틀라스 공간, 폴백 확인 |
| Scene에서는 보이는데 Game에서는 안 보인다 | Canvas 활성 상태와 Render Mode, 텍스트 위치·색·크기 확인 |
| 글자가 잘린다 | Rect Transform 상자 크기와 TMP 줄바꿈·Overflow 설정 확인 |
| 자동으로 너무 작아진다 | Auto Size를 끄고 Font Size와 상자부터 조절 |
| 어떤 글자만 모양이 다르다 | 다른 서체의 폴백으로 표시되는지 확인 |
| 재질(외곽선/그림자)을 바꾸니 다른 글자도 다 바뀐다 | 공용 머티리얼을 수정했는지 확인. 별도 Material Preset을 만든 뒤 해당 텍스트에 연결 |
| 에디터에서는 되는데 빌드에서는 안 된다 | 폰트 참조와 Dynamic 원본 포함 여부, 실제 빌드의 경고 확인 |

## 참고 자료와 확인 범위

이 글은 메뉴를 따라가는 입문 절차와 운영 제안을 함께 정리했다. 예시 숫자는 실습 시작값이며 출시 보증 설정이 아니다.

초안은 Unity 6000.6.0f1에 설치된 uGUI 패키지의 메뉴·Inspector·동봉 문서를 대조한 내용을 바탕으로 작성됐으며, 이번 보완에서는 uGUI 2.0 공식 문서와 공개 소스의 설명을 추가로 참고했다. 공개 저장소의 main 소스가 설치된 패키지와 완전히 같은 버전이라는 뜻은 아니다. 프로젝트에서는 Unity 버전과 함께 Package Manager의 Unity UI(uGUI) 버전도 기록한다.

실제 Inspector 화면 캡처, 에디터 실습, 목표 기기 빌드·성능 측정은 아직 수행하지 않았다. 본문의 비교 절차와 숫자는 측정 결과나 출시 보증값이 아니다. 게시 전에는 설치 버전에서 편집 가능한 항목·재생성 절차와 실제 표시 결과를 확인하는 것이 좋다.
