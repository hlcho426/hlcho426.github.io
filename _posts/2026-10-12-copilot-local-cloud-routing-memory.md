로컬 AI를 검토할 때 모델 파일이 메모리에 들어간다는 사실만으로 충분할까? Microsoft는 Copilot의 로컬·클라우드 선택 계획을 설명하며 문맥과 실행 도구의 경계도 다룬다. 발표의 대상 하드웨어와 제공 계획을 실제 이용 가능 상태와 구분해 정리한다.

## 무슨 일이 있었나
{:.briefing-heading}

### 계획 — 작업에 따라 추론 위치를 선택한다

10월 7일 설명은 월말까지 로컬·클라우드 추론을 자동 조정하는 경험을 제공할 계획이라고 밝힌다. 명시적으로 로컬 모델을 고르는 흐름과 자동 선택을 구분한다. 이미 모든 환경에서 자동 선택이 제공된다는 뜻은 아니다.

### 조건 — 가중치 외에도 메모리가 필요하다

발표의 MAI Code 1.1 Flash는 총 1,370억·활성 68억 파라미터의 MoE 모델이다. 파라미터는 모델의 수치 가중치이고, MoE는 요청 처리에서 일부 전문가를 사용하는 구성이다. 장치용 양자화 모델은 약 53GB, 256K 문맥에서 최대 메모리는 75.5GB로 보고됐다. 대상 예시 하드웨어는 최대 128GB 통합 메모리다.

문맥 캐시·운영체제·다른 앱도 메모리를 사용한다. 수치를 일반 개발 PC의 요구 사양이나 속도로 그대로 옮기면 안 된다.

### 경계 — 로컬 추론과 도구 실행 권한은 다르다

Microsoft는 모델 선택·오프라인 여부·도구 격리를 구분한다. 로컬 모델이어도 셸과 연결 도구의 접근 권한은 별도이고, 원격 연결이 사라지는 것도 아니다. 발표된 실행 경계를 실제 사용 설정과 대조해야 한다.

## 왜 중요한가
{:.briefing-heading}

**분석:** 로컬 모델 도입은 비용만이 아니라 작업 중 메모리와 지연, 품질을 함께 보는 판단이다. 엔진·IDE가 실행 중인 환경에서 모델만 단독으로 시험한 수치를 기대하면 차이가 생길 수 있다.

### 구체적인 작업 예시 — 같은 코드 탐색 과제

**설명용 예시:** 공개 저장소의 특정 기능을 찾는 읽기 요청을 준비한다. 엔진과 IDE를 켠 상태에서 작은 로컬 모델과 기존 방식의 결과를 비교한다고 가정하자. 위치가 맞는지, 대기 시간이 늘었는지, 다른 앱 사용이 불편해졌는지 기록한다.

읽기 작업의 성공을 자동 수정 권한의 근거로 쓰지 않는다. 모델이 답을 만드는 위치와 실제 파일을 바꾸는 도구의 권한을 별도로 정한다. 이 글에서는 모델이나 하드웨어를 시험하지 않았다.

### 어떤 개발자에게 관련 있나 · 지금 도입할 만한가

**필자의 판단:** 로컬 AI와 기존 개발 도구의 자원 경쟁을 검토하는 작업자에게 참고 자료다. 발표만 보고 PC를 구매하기보다 제공 환경과 실제 작업 성능을 확인하는 쪽이 먼저다.

## 개발에 적용할 점
{:.briefing-heading}

- 모델 파일뿐 아니라 문맥 캐시와 동시에 실행할 앱의 메모리를 고려한다.

- 제공 예정 기능과 현재 선택 가능한 제공자·모델을 따로 확인한다.

- 모델 위치·외부 연결·파일 및 셸 권한을 별도 항목으로 기록한다.
