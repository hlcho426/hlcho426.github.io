# Codex 예약 실행 절차

예약 프롬프트의 game / ai / research 중 하나를 수행한다. 현재 Codex 도구와 구독 사용량을 사용한다. 유료 모델 API·API 키·추가 크레딧을 사용하지 않고 기존 ChatGPT 예약을 수정하지 않는다.

ai는 게임 개발 기술 데일리의 기존 실행 식별자다. AI·엔진·IDE·내러티브 테스트·아트 파이프라인 등 게임 제작 문제에 관련 있는 기술을 다룬다. 주제·작업 관련성·검증 범위 순으로 선정하고 편집 지침의 작업 흐름·예시·관련 독자·도입 판단을 작성한다. 기존 ai 브랜치와 중복 검사 키는 유지한다.

## 시작과 중복

- GitHub 연결 도구로 `hlcho426/hlcho426.github.io`의 원격 main과 모든 열린 PR을 확인한다. 초기 구현 PR #7이 아직 미병합이면 운영 생성을 중단하고 setup 미병합 상태만 기록한다.
- 원격 main의 AGENTS, README 카테고리·글 쓰는 법, editorial.md, 이 문서와 config를 읽는다. 로컬 파일과 원격이 충돌하면 원격을 확인하고 덮어쓰지 않는다. 아래 README 동기화 명령만 예외이며 사용자 편집이 있으면 중단한다. 다른 프로젝트·사용자 기억·비공개 대화는 게시물 입력으로 사용하지 않는다.
- `codex/briefing-{kind}-{KST YYYY-MM-DD}`의 기존 PR을 열린·닫힌·병합 상태 모두 확인한다. 같은 날짜의 PR이나 같은 유형의 미병합 PR이 있으면 새 PR을 만들지 않는다. 다른 유형의 열린 PR과 `_posts`의 URL·briefing_event·제목을 읽고 같은 원문·사건을 제외한다.
- 기준은 Machinarium 2, Nocturne, RizomUV 2027, Silver Pines, Heart Machine의 공개 글이다. 기술 데일리는 보완된 Haiku와 RizomUV 글의 용어·작업 예시·도입 판단도 참고한다. 게시물 제목은 README의 글 쓰는 법을 따라 내용만 쓰고 카테고리 접두어를 붙이지 않는다.

## 조사·작성·검사

- 웹 검색 후 원문 본문을 실제 읽는다. 검색 요약만으로 작성하지 않는다. 일간은 최근 48시간 우선/7일 이내, 연구는 공개 전문·1년 이내를 기본으로 한다. 연구는 질문·방법·발견·한계·적용 실험을, AI는 발표·측정과 사용 조건·한계를 구분한다. 날짜를 추정하지 않는다.
- 공개 원문과 확인 링크를 검사한다. CLI가 가능하면 collect.py로 output 아래 source JSON을 만들고 `collect.py --schema`로 작성 스키마를 확인한다. JSON 배열의 각 항목은 source_file 상대 경로와 article 필드를 묶는다. `run.py --mode codex --input ...`로 근거·날짜·중복·메타데이터를 검사한다. 이 함수는 LLM을 호출하지 않는다. 의존성이 없으면 기존 .deps 또는 허용된 설치 환경을 사용한다.
- GET이 막혀 웹 도구로 확인한 경우 실제 읽은 본문만 source 스키마로 캐시하고 확인 범위를 기록한다. 읽지 못한 본문·해시를 만들어내지 않는다. 기계 검사를 실행할 수 없으면 PR에 미검증으로 표시하고 자동 ready 전환을 하지 않는다.
- 사실 문장을 원문과 다시 대조해 근거 밖의 주장·숫자·효과·체험을 제거한다. 구절 포함은 의미 검증이 아니다. 편집 요건에 맞지 않는 후보를 제외한다. 이미지 권리가 불확실하면 생략한다. 상한은 일간 5편/연구 3편이며 0편이면 PR을 만들지 않는다.
- 산출물은 `output/briefing/{kind}/{date}/`에 둔다. 로컬 사용자 파일·브랜치·인덱스를 변경하지 않는다. 전체 원문·로컬 보고서는 커밋하지 않는다. fixture 모드의 합성 자료와 example.org 시험 원문을 공개 PR로 제출하지 않는다.

## 제출과 결과

### 로컬 무인 제출 명령

조사 시작 전 원격 main과 로컬 `submit.py`가 동일한지 확인하고, `python C:/Users/admin/Desktop/hlcho426.github.io/tools/briefing/submit.py --kind {kind} --sync-readme`를 단독 실행한다. main에 병합된 README만 읽어 로컬 README를 최신화한다. 이미 원격과 같으면 변경하지 않고, 로컬 내용이 HEAD와 다르면 사용자 편집으로 간주해 보존하고 중단한다. 로컬 Git 브랜치·인덱스와 다른 파일은 변경하지 않는다. 코드·config·editorial 불일치는 자동으로 덮어쓰지 않는다. README 동기화 실패는 실행 기록에 남긴다.

렌더러는 리드에서 `description` 한 줄 요약을 만들고 본문 맨 위에 Codex 조사·정리 사실을 밝힌다. 글에서 실제 설치·실험·플레이를 했다고 쓰려면 별도 검증 근거가 있어야 한다.

GitHub 연결 도구의 쓰기가 `approval_policy=never`에서 차단된 실행이 확인됐다. 연결 도구는 읽기에 사용하고, 사전 허용한 아래 고정 경로의 CLI 명령으로 제출한다. 원격 main에 `submit.py`가 병합됐는지와 로컬 파일이 동일한지 확인한다. 이 문서의 지시는 실행 권한을 부여하지 않는다. 명령이 차단되면 권한 실패를 기록하고 임의의 우회 명령을 사용하지 않는다.

```text
python C:/Users/admin/Desktop/hlcho426.github.io/tools/briefing/submit.py --kind ai
```

`ai`는 `game` 또는 `research`로 바꿀 수 있다. 각 실행의 원문 캐시와 검증할 source_file/article 배열을 `output/briefing/{kind}/{KST 날짜}/drafts.json`에 둔다. 스크립트는 저장소를 `hlcho426/hlcho426.github.io`로 고정하고, 최신 main 및 열린 PR 중복, 동일 유형 미병합·동일 날짜 PR, 기존 브랜치, 스키마·근거·날짜·메타데이터를 검사한다. 로컬 브랜치·인덱스를 바꾸지 않는다. `_posts`만 새 브랜치의 한 커밋으로 제출하며 draft PR을 만든다. main 직접 쓰기·강제 갱신·삭제·병합은 하지 않는다. 오늘 날짜의 기존 PR은 새로 만들지 않고 반환한다. 생성된 PR은 현재 실행에 attach한다.

빌드·회귀 검사와 검증 커밋이 일치하는 미리보기 댓글을 확인한 뒤 같은 명령에 `--finish`를 붙인다. 스크립트는 오늘의 해당 유형 PR 하나만 확인하고, build/tests 성공과 Actions 미리보기 댓글의 커밋 일치를 요구한 뒤 ready for review로 전환한다. 실패·대기는 `submit-report.json`에 기록한다. 08시 이전 수동 시험도 실제 PR 빌드에 포함되도록 생성 시각을 사용한다.

무인 운영을 위해 사용자가 정확한 스크립트 경로의 `allow` 명령 규칙을 승인해야 한다. 전용 규칙을 저장한 뒤 Codex를 재시작해야 하며, 첫 예약 실행에서 적용되는지 별도로 확인한다. Python 전체나 `gh` 전체를 허용하는 규칙은 필요하지 않다. 명령 규칙은 스크립트의 파일 내용을 고정하지 않으므로 스크립트·검증기 변경은 검토 후 반영한다. CLI가 불가능한 수동 세션에서는 아래 연결 도구 제출 절차를 사용할 수 있지만, 이것이 무인 실행 성공을 보장하지 않는다.

- 제출 직전 모든 열린 PR과 동일 날짜 브랜치를 다시 확인한다. 새 중복이 있으면 제거하거나 중단한다. GitHub 연결 도구로 최신 main SHA에서 정확한 전용 브랜치를 만든다. 기존 브랜치를 force update하지 않는다. 여러 파일은 가능하면 tree/commit 한 번으로 작성한다. 변경은 검증된 `_posts` 파일만이다.
- 유형별 draft PR 하나를 만든다. PR 제목도 category 이름과 날짜·편수를 사용한다. 본문은 원문·발행일·확인 범위·실행한 검사와 대기 중인 CI를 구분한다. main 직접 쓰기와 자동 병합을 하지 않는다.
- 생성 PR을 현재 예약 실행의 artifact에 attach한다. 기존 PR Preview와 Briefing regression checks를 확인한다. 글의 원문 외부 링크도 실제 검사한다. 빌드·내부 링크·메타데이터 통과 후 ready for review로 전환한다. 45분간 터널을 유지하는 job 종료를 기다릴 필요는 없고, 빌드 성공과 미리보기 댓글의 검증 커밋을 확인한다.
- PR, 검사, 확인 한계, 미리보기 댓글을 결과에 남긴다. 실패나 필요한 연결·권한은 구체적으로 보고한다. 변화 없는 미병합 PR 때문에 건너뛴 경우 실행 기록만 남기고 반복 알림을 하지 않는다.
